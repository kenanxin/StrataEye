# 删除地表场景设计

## 目标

按照教师审查意见，从最终产品和演示材料中完整移除地表场景。系统只保留井下数字孪生、顶板灾变预警、真实数据回放、三端协同闭环和六智能体研判。

## 方案选择

采用产品级完整删除方案。该方案不只是隐藏按钮，而是停止构建和加载地表地形及工业广场，删除地表相机预设和交互入口，并让旧的地表链接安全回落到井下场景。历史设计文档保留为开发记录，不参与产品展示和运行。

## 页面与路由

- 删除 Three.js 画面中的“地表”按钮和地上／地下切换容器，只保留井下场景。
- 应用默认进入 `underground`。
- 访问带有 `view=surface` 的旧链接时不报错、不显示空白，统一按井下模式初始化。
- 不再导出或调用 `switchToSurface`。
- 场景加载提示只描述井下 1206 工作面，不再出现地表、露天采区或工业广场文案。

## Three.js 场景

- Mine V2 不再创建 `surfaceRoot`。
- 不再导入或调用地形、地表工业广场及地表高度函数。
- 删除仅供 Mine V2 地表场景使用的 `surface-campus.js`、`terrain.js` 和 `terrain-profile.mjs`。
- 保留地质剖面、地下巷道网络、1206 工作面、井下设备、传感器、风险场和灾害演示。
- 将原“总览”相机改为井下巷道总览；运行时只允许 `overview`、`underground` 和 `exit` 三种井下相关预设。
- 标签逻辑取消地表分支，初始化后直接使用井下标签模式。

## 兼容与安全边界

- 不改动真实 CSV、XGBoost 模型、六智能体接口、三端权限和预警闭环状态机。
- 不删除可能被井下场景共用的 HDR、岩石、金属、输送机和摄像头资源。
- 旧版未启用的场景实现保留在仓库中，避免扩大到无关重构；最终页面和 Mine V2 运行时不会加载或进入其中的地表功能。
- 设备焦点映射若仍存在地表目标，应删除或改为井下有效目标，禁止自动切换到不存在的地表相机。

## 文档与录屏稿

- 从 `D:\矿业\图片.docx` 的最终录屏流程和配音稿中删除地表场景相关表述。
- 数字孪生镜头只展示井下 1206 工作面、风险热点和监测设备。
- README 的最终作品说明调整为井下数字孪生，不再把地表场景列为演示能力。
- 历史方案和 QA 文档保留原始内容，作为开发过程记录，不作为最终演示材料。

## 测试与验收

- 新增或调整契约测试，要求页面中不存在 `data-view="surface"` 和“地表”切换按钮。
- 相机预设和控制限制不得包含 `surface`。
- Mine V2 构建文件不得导入地表场景模块，也不得暴露 `surfaceRoot`。
- `view=surface` 必须初始化为 `underground`。
- 删除地表专用测试，保留并通过井下拓扑、设备、风险场、三端和六智能体测试。
- 运行完整 Node 测试和离线提交预检。
- 在本地和生产 Chrome 中验证井下场景正常加载、无空白、无控制台错误、无地表入口。
- 推送 `main` 和 `deploy/mine-v2-balanced`，确认 Vercel 与 Render 均部署新提交。

## 完成标准

教师和演示人员无法从页面按钮、URL参数或设备跳转进入地表场景；浏览器只呈现井下数字孪生。项目核心数据、算法、三端协同和六智能体功能保持正常，Word 录屏稿与最终页面一致。
