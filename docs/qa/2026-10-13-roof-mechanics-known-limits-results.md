## 结果

两种输入在每组内共享完整工况划分。验证集均按事前规则选择 XGBoost，且四个选择均达到预设 Macro-F1、低类误报比例及类 3 支持条件。下表给出冻结选择后的观测，范围仅描述两组固定复制；未估计置信区间。

| 复制 / 输入 | 验证 Macro-F1 | 测试 Macro-F1 | 域外 Macro-F1 | 测试类 3 recall |
|---|---:|---:|---:|---:|
| a / raw4 | 0.5434 | 0.5472 | 0.5806 | 0.3737 |
| a / known_limits4 | 0.9268 | 0.9437 | 0.9455 | 0.9697 |
| b / raw4 | 0.5688 | 0.5397 | 0.5430 | 0.3333 |
| b / known_limits4 | 0.9213 | 0.9365 | 0.9477 | 0.9422 |

测试 Macro-F1 的两组描述范围为 raw4 0.5397–0.5472、known_limits4 0.9365–0.9437；本模拟器中已知限值提供了明显的预测信息。known_limits4 对每个工况使用模拟器的精确位移限值、支护容量和抗弯强度，实际取得和校准这些限值的误差尚未测量。因此差异体现信息条件变化下的模拟表现，不能作为现场改进幅度。

事件告警把预测等级≥2 或≥3 分开计算。下表 `及时/越界` 是首次极限越界前 1–3 步、且对应未来目标为类 3 的工况数；`非越界告警/非越界` 是在有监督观测的未越界工况中出现至少一次告警的工况数。所有逐事件提前步数及完整四类矩阵留在每组 `metrics.json`。

| 复制 / 输入 | 测试等级≥2：及时；非越界告警 | 测试等级≥3：及时；非越界告警 |
|---|---|---|
| a / raw4 | 56/66；32/34 | 30/66；15/34 |

等级≥2 时，两组 known_limits4 的非越界告警负担仍很高；等级≥3 的负担较低但并非零。告警等级是本次固定评估口径，没有按测试结果搜索阈值。域外仅改变梁跨度范围 `(12,14] m`，其他模拟采样机制相近；高域外分数并未检验一般分布转移。

已知限值当前类别延续参照在测试等级≥2 下同样及时检出 a 的 66/66、b 的 75/75 个越界工况，其非越界告警分别为 24/34、20/25。因此该口径的全事件检出没有体现相对这一物理参照的优势；主要差异见未来等级分级、等级≥3 检出和告警负担。

## 方法与核验

每组 500 个域内、100 个域外工况，请求 32 个准静力加载步。a/b 的生成与划分种子分别是 `(41101,42101,43101)` 和 `(41102,42102,43102)`。排除 step 0 后各有 15,097 与 15,286 条观测；每组工况数为训练 300、验证 100、测试 100、域外 100，组间交集为零。两个输入严格同源，raw4 为当前挠度、因果挠度增量、最大支护力、最大弯曲应力；known_limits4 将它们依次除以位移限值、位移限值、支护容量（kN）、抗弯强度。未来目标是随后三个已观测加载步的最高类别，阈值 0.5/0.8/1.0，首次越界后停步。尾部不足三步仅在确认首次越界时保留。

RF 与 XGBoost 使用固定参数和仅训练标签产生的权重；XGBoost 仅以验证集 `mlogloss` 早停。验证候选须 Macro-F1≥0.50、低类误报比例≤0.20 且真实类 3 存在，再依类 3 recall、Macro-F1、XGBoost 平手顺序选择。测试与域外结果均在选择冻结后计算。多数类和已知限值当前类别参照与全部模型在验证、测试、域外的完整行/事件结果均保留，零分母记 `null`。本结果与 V1 使用不同新种子；V1 原始四观测测试类 3 分级漏识别偏高仅作历史背景，不能作配对比较。

输出在不存在的目录新建。`protocol.json` 在生成训练前写入固定值、源码哈希、UTC 时间及教师 CSV 初始哈希。读回重建两组所有未来目标与归一化特征，检查行/工况覆盖、分组、计数、模型原生四特征四类、XGBoost 重载预测、事件指标及验证选择；RF joblib 仅保存，不加载外部 pickle。严格 JSON 解析和 SHA-256 清单覆盖除清单自身外的 26 个文件，全部通过。教师 CSV 前后 SHA-256 相同，均为 `86d4c2fb192721b2745f00076aeb00cf351c654ed936ddb098bfa6217e30ac6a`。清单自身 SHA-256 为 `031e0801d980caf09893eecbf15139ce0b3d0bd541d76289a2139df73e7d4537`。完整命令、版本和参数见协议文件。

代码审阅后增加了独立回读对 `protocol.json` 所要求的域内/域外数量、总数和请求步数的交叉核验，以及“改动测试/域外标签后已拟合模型预测不变”的回归断言。更新后的审计代码只读复核原正式存档，再次通过：每组分别检查 600 个工况和 15,097/15,286 条合格观测，26 个文件的原清单 SHA-256 仍如上。原 `protocol.json` 的源码哈希记录的是正式训练时的修复前代码；修复后的审计代码哈希另记于证据 JSON。正式协议、模型、预测、指标和输出文件未重写，结果也未重新选择。

最终全分支审阅后，回读进一步核对排除 step 0 前重建的监督行数与原 `metadata.row_count` 一致。只读复核原存档得到 a/b 各 15,697/15,886 行，均等于合格行数加 600 个初始行；原清单仍核验通过。此最终审计的代码哈希在证据 JSON 的 `post_final_readback` 单独记录，保留此前 `post_fix_readback` 的历史记录。正式输出与训练协议仍保持原样。
