# StrataEye 界面设计

2026-10-17。本地基于 `0e683d0` 进行界面优化，应用 frontend-design 技能。范围包含登录、企业、监管、智库、只读端共用布局、管理中心、支护分析及协同对话框。

## 设计方向

以井下空间为主视觉、以风险证据为阅读主线。三维场景保留矿灯与岩层的真实色彩，操作界面使用深蓝层次，与场景的暖色光照形成清晰分区。橙、红、黄、绿继续承担风险或状态含义。

| 用途 | 色值 |
| --- | --- |
| 基底深蓝 | `#0b1626` |
| 面板岩蓝 | `#122238` |
| 抬升表面 | `#192e46` |
| 结构边线 | `#2a4059` |
| 操作蓝 | `#72adf5` |
| 感知青 | `#78dce7` |

字体使用本地 Noto Sans SC 可变字体子集，CSS 别名 Strata Sans；支持 100–900 字重。正文 12–14px，模块标题 15–18px，页面标题 24–32px，登录品牌标题 48–96px。数据使用 Bahnschrift 及系统字体回退，等宽字体只用于记录号、版本等需要对齐的元信息。字体许可证见 `assets/fonts/OFL.txt`；生成工具见 `tools/build-ui-font.py`。

内容左对齐，风险数字独立对齐。企业端以三维场景为中心；监管端以事件核验与证据队列为主；智库端保留分析导航、智能体工作流及科研图表。

```text
企业端：品牌 / 身份 → 演示控制 → 事件进度 → 协作记录
        设备清单 | 三维井下场景 | 风险与处置
        多源监测 → 历史回放 → 支护分析

监管端：身份 → 事件进度 → 风险概览 → 处置核验 → 证据队列
智库端：身份 → 事件进度 → 模型解释 → 复盘 → 分析导航 | 图表与研判
登录页：井下场景 / 品牌与用途 | 工作账号登录
```

设计复核时，移除了无业务顺序的卡片编号、装饰角标、琥珀色边框泛用及过密英文标签。保留的六阶段编号和事件进度具有实际顺序含义。共享主题集中在 `css/strata-theme.css`，作为现有业务组件的最后一层，避免各端继续追加相互矛盾的视觉约定。

## 本地运行

根目录执行 `npm ci` 后运行 `npm start`，打开 `http://localhost:8092/login`。Node.js 要求 18 及以上；默认本地认证和文件事件存储，不依赖外部认证服务。已存在的本地演示账号可用于企业、监管和智库页面。生产超级管理员由既有认证服务提供；本轮没有建立生产账户或修改权限。

## 验证方式

浏览器检查涵盖 1440px 桌面与 390px 手机视口、登录、三个业务端、三维场景及图表；管理后台使用浏览器内模拟用户列表和审计响应进行视觉检查，不作为真实账户管理验收。检查截图与临时记录存放在忽略目录 `tools/.generated/`。最终测试结果见项目长期上下文的 2026-10-17 本地界面优化记录。

新增的字体和 SVG 标志均为本地资源。更新界面字符后可重新生成字体子集；未包含的字符由系统字体补足。色彩含义、模型输入、训练权重、角色权限和保存事件接口沿用对应实现。
